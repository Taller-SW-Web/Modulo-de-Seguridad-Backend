## Contrato definitivo

```java
interface ProteccionPort {
    EvaluacionProteccion evaluar(CuentaSnapshot cuenta, Instant ahora);
    ResultadoFallo registrarFallo(CuentaSnapshot cuenta, HuellaFallo entrada, ContextoPeticion contexto);
    void completarLogin(UUID usuarioId);
    ResultadoDesbloqueo desbloquear(PruebaEnlace prueba, ContextoPeticion contexto);
}
```

Todos los DTO son propios de proteccion.application.dto:
- CuentaSnapshot(usuarioId, correo, estadoBase, bloqueosSeguidos, intentosFallidos):
  proyección acotada desde el DTO de Eva, sin entidad ajena.
- EvaluacionProteccion(estado, permiteLogin, permiteRenovar, tipoBloqueo,
  bloqueadoHasta, revisionBloqueo, intentosFallidos, bloqueosSeguidos).
- ResultadoFallo(estado, intentosFallidos, bloqueosSeguidos, revisionBloqueo),
  estado IGNORADO/REPETIDO/CONTADO/BLOQUEADO.
- HuellaFallo(byte[] secretoEfimero, String correoIntentado) es entrada efímera
  AutoCloseable: conserva bytes exactos para calcular el HMAC con la racha
  persistida, NO un tag elegido por HTTP. cerrar borra bytes; toString redactado.
  Es distinto del modelo persistido domain.model.HuellaFallo.
- PruebaEnlace(valor) y ResultadoDesbloqueo DESBLOQUEADA/INVALIDA/EXPIRADA.

Se conservan las cuatro operaciones acordadas, sin exportar dominio/JPA de
ninguna capacidad. Los adaptadores consumidores deben mapear el snapshot
de Eva al DTO propio; no importar servicios/repositorios de protección.

## Comportamiento

Solo una contraseña incorrecta distinta sobre ACTIVO suma. Se registra también
la repetida, inexistente, inactiva, pendiente o bloqueada sin sumar. No hay ventana
ni partición por IP. Racha/HMAC/key_id persisten; no usar SHA sin pepper o contador
legacy de credencial. El servicio descarta la copia de bytes después de generar
la huella; el caller debe cerrar HuellaFallo al acabar la petición.

Evaluar es lectura sin escritura: automático vigente impide login pero permite
renovar; manual impide ambos; en el instante hasta ya es ACTIVO con contador
efectivo cero, sin job/evento. La siguiente mutación renueva racha/huellas.
Solo completarLogin correcto resetea también bloqueosSeguidos, nunca el desafío.

RegistrarFallo y completarLogin son MANDATORY. El coordinador de login toma
guard ADMIN → cuenta y confirma revisión de credencial antes de registrar.
El proveedor no reclama un guard nuevo después de cuenta, evitando invertir
el orden aprobado. Los tests usan guard/cuenta reales mediante sus puertos.
Desbloquear, como coordinador público, toma él mismo guard → cuenta → filas propias.

Si un legado tiene contador positivo sin racha verificable, falla técnicamente:
no inventa huellas pasadas ni borra fallos para hacer pasar la prueba; requiere
revisión de esa historia antes de habilitar ese camino. No se fabrica un backfill.
