## Cómo compone las capacidades (sin SQL sobre tablas ajenas)

- **Identidad (Eva):** `AltaCuentaPruebaInterna` → `AltaCuentaPruebaAdapter`.
- **Credencial (Juan José/Luis):** `CredencialPruebaInterna` usa el mismo
  `PasswordHasherPort` que verifica el login, y guarda la credencial más la primera
  entrada del historial. La clave se valida antes con `CredencialesPort.validarNueva`
  (política real, incluida la lista común y los datos personales).
- **Roles (Sergio):** `RolesPruebaInterna` añade los roles que falten.
- `CargaCuentasPrueba` (configuración) lo ejecuta todo en **una** transacción
  READ_COMMITTED al arrancar.

Reglas: si el UUID ya existe, la cuenta no se toca, así que repetir la carga no
duplica ni sobrescribe lo cambiado en la demo. Si el correo pertenece a otra
cuenta, o la clave incumple la política, se revierte toda la carga. El log solo
muestra etiqueta, UUID, correo, roles y si se creó.

## Configuración (nunca en Git)

```bash
G7_FIXTURES_CUENTAS_HABILITADAS=true
G7_FIXTURES_CUENTAS_CLAVE=<clave que cumpla la política; se comparte por canal privado>
G7_PASSWORD_COMUNES_ARCHIVO=<ruta a la lista común>   # obligatoria para validar
```

La clave no puede contener el nombre ni la parte local del correo de ninguna
cuenta (por ejemplo «cliente», «prueba», «admin» o «vendedor»).
