## Entrega

Modelos y DTO puros; SesionesPort recibe identidad previamente resuelta,
sin depender de LoginService ni MfaService. Apertura persiste familia estable,
refresco aleatorio de 32 bytes (solo SHA-256 en DB, siete días) y asociación de
cada acceso RS256 de 900 s. Firma/persistencia fallidas revierten el conjunto.

Contrato definitivo en `sesion.application.port.in`:

```java
interface SesionesPort {
    SesionIniciada abrir(UUID usuarioId, IdentidadAutorizada identidad, ContextoPeticion contexto);
    ContextoSesion resolverAcceso(AccesoVerificado acceso);
    RenovacionResultado renovar(SecretoRefresco secreto);
    CierreResultado cerrar(SecretoRefresco secreto);
    void revocarTodas(UUID usuarioId);
    void revocarOtras(UUID usuarioId, UUID familiaActual);
}
```

DTO en sesion.application.dto. AccesoVerificado(sub, jti) procede de FirmaPort,
nunca de un familiaId HTTP. ContextoSesion identifica usuario/familia/jti y
expiración persistidos. IdentidadAutorizada contiene identidad/roles/permisos
ya resueltos. SesionIniciada redacta tokens en toString; no se registran secretos.

Único bean productivo de SesionesPort. Abrir, resolver y revocaciones exigen
transacción existente (MANDATORY), con cuenta previamente bloqueada por el
coordinador. Resolver no es readOnly: utiliza un lock de escritura real.
Revocar familias sigue el ORDER BY UUID de PostgreSQL, no UUID.compareTo Java.

La raíz bloqueada se refresca explícitamente; el token se relee mediante
proyección escalar actual, sin clear() del contexto del coordinador.
Se conserva el INSERT de acceso que rechaza jti repetido; no se restaura merge.
